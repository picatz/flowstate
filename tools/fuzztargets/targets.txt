# Every fuzz target in this module, and the tiers that run it. This file is the
# one written source of that list: the Makefile's fuzz-smoke target loops over
# it, .github/workflows/deep.yml's fuzz-deep job loops over it, and tools/gate
# derives from it the set of packages whose affectedness decides whether the PR
# lane's fuzz-smoke job runs. CI's fuzz-smoke job runs `make fuzz-smoke`, so it
# reads this file too, at one remove. A new target therefore lands here, in one
# place, and tools/fuzztargets' own test fails if it lands anywhere else — it
# walks the tree for `func Fuzz…(f *testing.F)` and compares the set.
#
# Columns, whitespace-separated: target, package directory (module-relative),
# tiers (comma-separated, no spaces).
#
#   smoke  30s per target, on every push and every PR whose diff can reach a
#          package holding a target. The bound that makes it safe to run that
#          often is what keeps the list here short of every target: the job's
#          budget is ten minutes and ten targets already spend most of it.
#   deep   10m per target, weekly, on a schedule. Every target belongs to this
#          tier — the deep tier is where a budget finds what 30 seconds cannot,
#          and nothing about a target argues for excluding it from a run that
#          nobody is waiting on.
#
# Lines beginning with # and blank lines are ignored.

# The signal payload decoder is deep-only, and the reason is the budget this
# file's `smoke` note names rather than anything about the target. Its package
# is the engine, whose test binary links the Temporal SDK and is the slowest in
# the module to compile — a smoke tier that already spends most of ten minutes
# would be paying that link for 30 seconds of fuzzing, and every other smoke
# target shares a binary with one that is already built. Nothing else argues
# for the exclusion: the bytes it decodes are a peer's, which is the strongest
# case for a tier there is, and it is why the target exists.
#
# The engine package does not boot its Temporal dev server for a fuzzing
# process — see `fuzzing` in engine/main_test.go — because the tiers run one
# command per target with no per-target flags and there would otherwise be
# nowhere to put the `-short` that boot needs.
FuzzSignalDeliveryDecode     pkg/flowstate/v1/engine        deep
