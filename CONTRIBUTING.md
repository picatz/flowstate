# Contributing to Flowstate

This guide is for people. The always-loaded contract for coding agents is [`AGENTS.md`](AGENTS.md); it holds the architectural invariants and the verification commands, and everything in it applies to your agent when you bring one. Read both once.

## What Flowstate is right now

Flowstate is intentionally super-alpha (#1216). There is no release, no tag, and no compatibility promise across the CLI, the Flowfile edition, the protobuf API, or the plugin SDK. Breaking and foundational changes are welcome when they improve the eventual model. What is not welcome is a change that violates an invariant in `AGENTS.md`, even when its tests pass.

## Build, test, verify

```sh
go build ./...                                   # the module
GOMEMLIMIT=1GiB go test -short -timeout 150s ./pkg/...  # a bounded targeted run
go run ./tools/gate                              # the diff-scoped gate: run this before opening or updating a PR
make check                                       # full CI parity, when the scope warrants it
make fmt                                         # never a bare gofmt; the Makefile uses the pinned toolchain
```

Without `-short`, as in `make check` and the gate, four packages boot a Temporal dev server in their tests (`engine`, `server`, `temporalclient`, `cmd/flow`); that is expected and takes about ten seconds each. The bounded run above passes `-short`, so no server boots: those packages run everything that does not need one and skip only the tests that do, which is why it finishes quickly and why the gate, not that run, is the bar before a pull request. `docs/CI.md` explains what CI runs and why.

Never kill test processes by name or pattern. Stop the PID you started.

## Issues

Open an issue from one of the templates. The shape the repository uses, and the one reviewers can act on, is: observed behavior with evidence, desired outcome, acceptance criteria a test can evaluate, constraints. A reproducer or a measurement beats an opinion. Search for the repository's existing spelling of a concept before proposing a new one; `docs/DSL.md` records most language decisions and why they were taken.

Labels: `kind/bug` is a defect with a reproducer; `kind/design-record` is a decision to be recorded before code; `kind/decision` is a choice the maintainer must make; `kind/umbrella` groups slices. Area labels (`cli`, `dsl`, `engine`, `auth`, `security`, `testing`, `documentation`, `observability`) say where.

## Pull requests

- One coherent change per PR, the smallest diff that delivers the outcome. Do not attach unrelated cleanup.
- Tests prove behavior, including the negative direction that would expose the regression.
- Generated files are regenerated by the tooling (`buf generate`, `flow docs generate`), never edited by hand.
- The PR template's six sections are the body. Say exactly what you ran and what it proved; a skipped or unavailable check is not verified, and saying so is fine.
- Commit subjects are `scope: lowercase imperative` (`engine: bound the walker's depth`). The body says why, not what the diff already shows.
- Behavior observable in both drivers (local and Temporal) needs a shared conformance case, not two tests.

Every PR runs the same gate you ran locally. A merge needs every applicable CI
and review channel green on the current head, not only required checks, and no
unresolved review thread. Maintainers can verify the remote evidence with
`go run ./tools/shipcheck --repo picatz/flowstate --pr NUMBER`. Auto-merge is not
used: a final push invalidates earlier review, and the PR is merged manually only
after exact-head review completes.

## Bringing an agent

Coding agents are first-class contributors here. The repository ships their configuration: `AGENTS.md`, Amp's Custom Ship procedure at `.agents/ship.md`, the skills under `.agents/skills/` and `.claude/skills/`, the Claude Code subagents under `.claude/agents/` that review and verify in a fresh context, and hooks under `.claude/settings.json` that refuse edits to generated files, check formatting, and guard merges. Point your agent at `AGENTS.md`; the same rules, gate, and PR shape apply to its work as to yours, and you own what it opens.

## Maintainers and decisions

Flowstate has one maintainer, [@picatz](https://github.com/picatz), who reviews and merges. Decisions are recorded where they are made: language decisions in `docs/DSL.md`, system decisions in `docs/ARCHITECTURE.md`, and everything else as a `kind/design-record` issue with the decision written into it. There is no roadmap document; the open `kind/umbrella` issues and the milestones are the roadmap. `docs/plans/` is agent-orchestration process, not product direction.

There is no review turnaround promise during super-alpha. If a PR sits, a polite ping on it is fine.

Becoming a maintainer is by invitation after sustained contributions that show the invariants have been internalised. The MIT license answers what happens to the code if the maintainer is unavailable; the repository's configuration is designed so that an agent given `AGENTS.md` can keep it verifiable.

## Security
